# 发票号码及金额提取工具

一个基于 **PySide6 / PyQt6** 的桌面小工具：批量导入发票文件（PDF、扫描件图片、Excel 台账、文本/XML），
自动提取**发票号码**与**金额**，勾选后导出为 Excel / CSV / JSON。

> 当前版本 **v0.1.0（界面首版）**：界面框架、导入、解析、勾选、导出链路已完整可跑；
> 解析规则（正则 + 大写金额 + 合计行校验）已经过内置用例自检。
> 请先在本地运行，把界面上的修改意见告诉我，我再迭代。

## 1. 快速开始

```powershell
# 1) 建议使用虚拟环境
python -m venv .venv
.\.venv\Scripts\activate

# 2) 安装依赖（Qt 界面 + PDF 解析 + Excel 读写）
pip install -r requirements.txt

# 3) 启动
python app.py
```

依赖文件说明（**这三个文件都刻意保持纯 ASCII 英文注释**，原因见下方"常见问题"）：

| 文件 | 内容 |
| --- | --- |
| `requirements.txt` | 必需项：PySide6、pypdf、openpyxl、xlrd、charset-normalizer |
| `requirements-ocr.txt` | 可选：pytesseract + pillow（扫描件/图片识别；装完还要另装 Tesseract 引擎） |
| `requirements-full.txt` | 上面两个的组合（不含体积很大的 PaddleOCR / PyMuPDF） |

> 国内网络如果下载 PySide6 很慢，可以换国内镜像，或改用更小的绑定：
> ```powershell
> pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
> # 或者：pip install PyQt6   （代码同样兼容，无需改任何代码）
> ```

常用命令：

| --- | --- |
| `python app.py` | 启动图形界面 |
| `python app.py --demo` | 启动并自动生成/导入 4 个内置演示文件，可直接体验全流程 |

想换 Qt 绑定（默认自动探测 PySide6 → PyQt6 → PyQt5）：

```powershell
pip install PyQt6
$env:INVOICE_QT_BINDING="pyqt6"   # 或 python app.py --binding pyqt6
python app.py
```

启动成功时会先打印一行绑定信息，便于确认真身：

```
[Qt] 使用 PySide6 6.12.0（python 3.12.2）
```

> 自己写扩展代码时注意一个坑：`ui.qt` 里的 `QtWidgets / QtCore / QtGui` 等名字是**绑定加载后**才被赋值的，
> 所以必须先 `from ui import qt`，调用 `qt.ensure_binding()`，然后才通过 `qt.QtWidgets` 取对象；
> 不要在加载绑定前写 `from ui.qt import QtWidgets`，那样拿到的是 `None`。
> `app.py` 已经按这个顺序写好了，照着改即可。

## 3. 能提取哪些字段

| 字段 | 说明 | 主要识别方式 |
| --- | --- | --- |
| 发票号码 | **核心字段** | `发票号码：xxx` / `No:xxx`；数电票取唯一的 20 位数字；传统票取 8 位数字；铁路电子客票取 20 位号码（`电子客票号` 不会被误当发票号码） |
| 号码后8位 | **核心字段（派生）** | 由发票号码自动算出（只保留数字后取末 8 位），手工修改发票号码后会自动跟着变；默认不显示，可在「显示字段」里勾上，导出时默认包含 |
| 价税合计 | **核心字段** | `价税合计（大写）…（小写）¥x`、`合计 ¥x ¥y`、大写金额「壹万零陆佰元整」、铁路票 `票价:¥x`、合计行兜底 |
| 金额(不含税) | 辅助 | 合计行中「金额 xxx 税额 xxx」的第一个数；缺失时用 `价税合计 - 税额` |
| 税额 | 辅助 | 合计行中的税额；缺失时用 `价税合计 - 金额` |
| 发票代码 | 辅助 | `发票代码 031002100311` |
| 开票日期 | 辅助 | `开票日期：2025年03月12日` → 统一为 `2025-03-12` |
| 销售方 / 购买方名称 | 辅助 | 「销售方信息 名称：xxx」「购买方 名称：xxx」（铁路票没有销售方，不会用购买方顶替） |
| 来源文件 / 页码 / 置信度 / 备注 | 溯源 | 自动记录；铁路票的 `电子客票号` 记在备注里 |

对 OCR 常见错字做了容错：`发 票 号 亏`、`价税合汁`、`发 票 代 马`、全角字符与多余空格等。

**多票一页**：一份 PDF/文本里含多张发票时，会按「发票号码」出现的位置切分，逐张输出（并标注序号）。

**金额校验**：`金额 + 税额 ≈ 价税合计` 时自动提示不一致，并把该行标记为「需复核」；置信度随之下降。

## 4. 各类文件的解析方式

| 文件类型 | 处理方式 | 额外依赖 |
| --- | --- | --- |
| 电子发票 PDF（有文本层） | 按坐标重建文本 → 正则解析 | `pypdf`（已装则优先用更快的 `PyMuPDF`） |
| 扫描件 PDF / 图片 (png/jpg/tif…) | 转图片 → OCR → 正则解析 | `PyMuPDF` + `pytesseract` 或 `paddleocr` |
| Excel / CSV 台账 | 自动识别「发票号码/金额」等表头直接读列；识别不到表头则整表转文本再解析 | `openpyxl`（xlsx）/ `xlrd`（xls） |
| 文本 / XML / JSON | 按 UTF-8/GB18030 自动识别编码后解析 | 可选 `charset-normalizer` |

### 已适配的票种

| 票种 | 识别要点 |
| --- | --- |
| 增值税专用发票 / 普通发票（传统） | 8 位发票号码 + 12 位发票代码 + `合计 ￥x ￥y` |
| 数电票（全电发票，20 位号码） | `价税合计（大写）…（小写）¥`；一页多票自动切分 |
| **铁路电子客票（高铁票）** | 20 位发票号码 + 开票日期 + `票价:¥208.00` + 购买方名称；`电子客票号` 记入「备注」而不是当发票号码 |

> PDF 解析做了两处加固：① 有些 PDF 的字体描述符同时写了 `/FontFile2` 与 `/FontFile3`，
> pypdf 会直接抛异常并被误判成"需要 OCR"，现在会先修掉多余键；
> ② pypdf 默认顺序提取中文常被拆成单字、金额符号错位，改为按坐标重建行文本。

### 关于 OCR（扫描件必看）

未安装 OCR 引擎时，程序仍可正常运行，只是**扫描件/图片无法识别**，标题栏会显示 `OCR：未安装` 的黄色标记。
两种方案：

```powershell
# 方案 A：Tesseract（体积小，推荐先试这个）
# 1) 先安装引擎：https://github.com/UB-Mannheim/tesseract/wiki ，安装时务必勾选 Chinese (Simplified)
# 2) 再装 Python 封装：
pip install -r requirements-ocr.txt

# 方案 B：PaddleOCR（中文发票更准，首次运行会下载模型，约数百 MB）
pip install paddleocr paddlepaddle pillow
```

安装后回到界面：菜单「提取 → 解析设置」里即可选择引擎、渲染 DPI（默认 300）、单文件最多 OCR 页数（默认 5）。

## 5. 导出

导出对话框可选：**范围**（选中项 / 全部）、**格式**、**保存位置**、**列**、**是否附加合计行**。

可导出的列（默认全选，含新加的 **号码后8位**）：

```
发票号码 | 号码后8位 | 发票代码 | 开票日期 | 金额(不含税) | 税额 | 价税合计
销售方名称 | 购买方名称 | 来源文件 | 文件路径 | 页码 | 置信度 | 备注
```

> 「号码后8位」是**派生列**：从发票号码里取数字部分的后 8 位，例如
> `26329116804010371685` → `10371685`、`12345678` → `12345678`（不足 8 位则留空）。
> 它随发票号码自动变化：在详情面板改正号码后，表格与导出都会同步更新。

| 格式 | 特点 |
| --- | --- |
| `.xlsx` | 表头冻结 + 蓝色表头 + 金额列 `#,##0.00` 数值格式，末尾可选「合计」行；需要 `openpyxl` |
| `.csv` | 默认 `utf-8-sig`（Excel 双击不乱码），可选 UTF-8 / GB18030；无第三方依赖 |
| `.json` | 含 `exported_at / count / totals / invoices`，金额为数值，便于二次开发对接 |

> 导出的金额列写的是**数值**（不是文本），可直接在 Excel 里求和。

## 6. 工程结构

```
invoice-extractor/
├─ app.py                  # 入口：启动界面 / --demo / --self-test / --env
├─ config.py               # 字段定义、支持格式、解析选项、默认设置
├─ requirements.txt
├─ core/                   # 业务内核（不依赖 Qt，可单测 / 命令行调用）
│   ├─ models.py           # InvoiceRecord / FileItem / FileResult
│   ├─ textutil.py         # 全角半角、金额解析、中文大写金额互转
│   ├─ extract.py          # 发票号码 / 金额等字段抽取（核心正则 + 校验）
│   ├─ reader.py           # 文件类型分派：PDF / 图片 / 表格 / 文本
│   ├─ pdf.py              # pypdf 与 PyMuPDF 双引擎 + PDF 转图片 OCR
│   ├─ ocr.py              # Tesseract / PaddleOCR 封装与可用性检测
│   ├─ tablereader.py      # txt/csv/xlsx/xls 读取与表头识别
│   ├─ exporter.py         # CSV / XLSX / JSON 导出
│   └─ sample_data.py      # 演示数据 + 自检用例
├─ samples/                # 演示用发票文本（虚构数据）+ samples/pdf 下的真实票据样本
├─ scripts/
│   ├─ ui_smoke_test.py    # 离屏界面冒烟测试（21 项：导入/解析/勾选/导出/详情/主题/筛选/删行）
│   ├─ layout_check.py     # 布局回归：字号 9/12/16pt × 多种窗口宽度，查文字截断与行重叠
│   └─ pdf_check.py        # PDF 解析回归：用 samples/pdf 下的真实票据校验号码/金额/购买方
└─ ui/                     # 界面层（PySide6 / PyQt6 双兼容）
    ├─ qt.py               # Qt 绑定兼容层（Signal/Slot/QAction 等统一）
    ├─ styles.py           # 浅色 / 深色 QSS 主题
    ├─ widgets.py          # 拖拽表格、卡片、标签等小部件
    ├─ canvas.py           # 结果表模型（勾选列）、文件表模型、委托
    ├─ files_panel.py      # ① 导入区
    ├─ results_panel.py    # ② 结果区（筛选、字段开关、导出按钮）
    ├─ detail_panel.py     # 详情/校正区（原文高亮）
    ├─ dialogs.py          # 导出对话框、解析设置、运行日志
    ├─ workers.py          # 后台解析线程
    └─ main_window.py      # 主窗口装配
```

分层原则：`core/` 只管业务、`ui/` 只管展示。以后换界面或做命令行批处理，`core/` 可直接复用。

## 8. 常见问题

| 现象 | 处理 |
| --- | --- |
| `pip install -r requirements.txt` 报 `UnicodeDecodeError: 'gbk' codec can't decode byte 0xb7` / `decoding with 'cp936' codec failed` | 这是 pip 在中文 Windows 上按 GBK 读取 requirements 文件导致的。本仓库的 requirements 已改为**纯 ASCII 英文注释**，请更新到最新文件；如果你自己往里面加了中文注释，请删掉中文或改用 `pip install PySide6 pypdf openpyxl xlrd` 直接安装 |
| 启动报「未找到可用的 Qt 绑定」 | 先跑 `python app.py --qt-debug` 看真实原因。常见情况：① 确实没装 → `pip install PySide6`；② 装到了别的解释器 → 用 `python -m pip install PySide6` 保证装进当前 venv；③ 报 `cannot import name 'QT_VERSION_STR'` 之类 → 属于旧版兼容层的问题，本仓库 [ui/qt.py](ui/qt.py) 已改为逐符号容错导入（PySide6 6.12 起 QtCore 不再导出 `QT_VERSION_STR`），更新代码即可 |
| 报 `AttributeError: 'NoneType' object has no attribute 'QApplication'` | 导入时序问题：在 `ensure_binding()` 之前就 `from ui.qt import QtWidgets`。改成 `from ui import qt` + `qt.QtWidgets`（`app.py` 已修好） |
| 控制台提示 `QFontDatabase: Cannot find font directory` | 仅在离屏（offscreen）测试模式出现，正常桌面运行不会出现，可忽略 |
| PySide6 下载太慢/超时 | 换镜像 `-i https://pypi.tuna.tsinghua.edu.cn/simple`，或改用 `pip install PyQt6`（代码自动兼容） |
| PDF 打开是空的 / 扫描件识别不到 | 装 OCR：`pip install -r requirements-ocr.txt` + 安装 Tesseract 中文语言包 |
| 提示「读取表格需要 openpyxl」 | `pip install openpyxl`（读 xls 则 `pip install xlrd`） |
| 导出 xlsx 报错 | 改选 CSV 格式，或 `pip install openpyxl` |
| 金额识别不准 | 在右侧详情面板直接改，或把「解析设置 → 严格金额模式」打开（不再用最大金额兜底） |
| 想从命令行批量跑 | `from core.reader import read_file` 配合 `core.exporter.export` 即可，无需界面 |
